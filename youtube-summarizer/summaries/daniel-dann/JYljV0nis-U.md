## Key insights
- **The problem Hedra addresses**: Most AI video workflows are fragmented — research happens in one tool, scripting in another, generation in a third. Hedra aims to consolidate all of this into one workspace.
- **Core architecture**: Hedra is built around an "agent" and a persistent canvas called a "space." Unlike a simple prompt box, the space retains context and lets the project evolve iteratively.
- **Research before generation**: When given a task, the agent does not jump straight to video creation. It first asks clarifying questions, researches the topic, and surfaces findings inside the same space — giving the project a more informed starting point.
- **Creative brief on the canvas**: After research, the agent produces a creative brief directly on the canvas, defining the audience problem, tone, and video structure. Daniel was able to request a stronger opening and earlier product reveal, and the brief updated without losing prior context.
- **Scene plan stage**: Before any media is generated, the agent presents a scene-by-scene plan. Daniel shortened the middle section and gave the product reveal more screen time — all without switching tools or re-explaining context.
- **Final video quality**: The generated video for FocusFlow matched the brief visually and narratively. The one noted issue was a slightly fast voiceover — flagged as an easy fix before export.
- **Iterative revision**: If the output needs changes, the user can continue the conversation and ask for targeted revisions to specific parts rather than restarting the entire project.
- **Connectors and integrations**: Hedra supports connectors to external tools including Google Drive, Notion, and Slack, allowing teams to pull in information or push completed work to existing workflows.
- **Skills feature**: Hedra includes "skills" for saving and reusing repeatable workflows, so users don't have to re-explain a familiar process each time.

- **Caveat on research accuracy**: Daniel notes that AI-surfaced research findings should be verified before publishing — Hedra provides a useful starting point, not a guarantee of factual accuracy.

## Patterns & frameworks

**The "Space" model (persistent creative canvas)**
A "space" is Hedra's core unit of work — a persistent environment where every stage of a project (research findings, creative brief, scene plan, final video) lives together and stays connected. Rather than a stateless prompt-response loop, the space retains context so earlier decisions inform later ones and revisions don't require starting over.

**Research-first pipeline**
Instead of generating immediately, Hedra's agent follows a sequential pre-production flow: (1) clarify the task, (2) research the topic, (3) produce a creative brief, (4) draft a scene plan, (5) generate media. Each stage is reviewable and revisable before moving to the next, reducing wasted generation cycles.

**Iterative brief refinement**
The creative brief is treated as a living document on the canvas, not a one-shot prompt. The user can request specific changes (e.g., "stronger opening," "earlier product reveal") and the agent updates the brief while preserving the research and context it was built from — a feedback loop rather than a restart.

**Skills (reusable workflow templates)**
Skills are saved process templates for repeatable creative tasks. Once a workflow has been defined and proven (e.g., a product launch video format), it can be stored as a skill and re-applied to future projects without re-explaining the full setup — analogous to a macro or playbook for the creative process.
