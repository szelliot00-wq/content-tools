## Key insights
- **Stop using the card immediately** — writing new data to an SD card after loss can overwrite deleted file space, making recovery impossible. No new photos, recordings, copies, or formatting.
- **Empty-looking cards are not empty** — Daniel's SD card showed as an empty folder on his computer, yet Recoverit found 217 files including 85 photos, demonstrating that deleted data often persists in unallocated space.
- **AI media search reduces manual sorting** — rather than scrolling through 217 results, Daniel used natural language descriptions to search scan results and narrow down matches, useful when you remember what a file looks like but not its filename.
- **Preview before recovering** — Recoverit allows previewing files before restoration so you can assess quality and completeness, avoiding the wasted effort of recovering unusable files.
- **Recovery and repair are two separate steps** — restoring a file does not guarantee it is playable. A recovered video may still have corruption requiring a dedicated repair process.
- **Automatic video repair** — Recoverit includes a repair workflow for damaged clips. Daniel tested it on a video that wouldn't play post-recovery, and it became playable after repair.
- **Always verify outside the app** — Daniel stresses opening recovered files in a standard image viewer or media player (not inside Recoverit) to confirm they are genuinely usable.
- **Save to a different location** — recovered files should never be saved back to the same SD card being recovered from, to avoid overwriting other recoverable data.

## Patterns & frameworks
**Stop-Before-You-Start Rule**
Before touching any recovery software, cease all activity on the affected SD card. The logic: deleted files occupy space that the OS marks as available — any new write can permanently destroy that data. The rule is: no new photos, no recordings, no copies to the card, no formatting.

**Scan → Preview → Recover → Verify workflow**
Recoverit's intended process follows four distinct stages: (1) scan the card to surface hidden/deleted files, (2) preview results to assess file integrity before committing, (3) selectively recover files you want to a separate location, (4) open recovered files in a standard application outside of Recoverit to confirm real-world usability.

**Recovery ≠ Repair (two-stage restoration)**
The video draws a clear distinction between *finding and restoring* a file (recovery) and *fixing corruption* within it (repair). A file can be successfully recovered but still unplayable due to structural damage. These are treated as separate workflows requiring separate steps, with repair running after recovery as an optional second pass.

**AI-assisted search within scan results**
Rather than manually browsing large scan outputs, the AI media search accepts natural language descriptions of the target file and filters results accordingly — a practical pattern for large card scans where filenames are unknown but visual content is remembered.
