# ChatGPT Work + Codex Tutorial: My Complete System at OpenAI | Jason Liu

Video ID: `ydTeb_I0b94`

## Summary
Jason Liu, a developer experience team member at OpenAI working on Codex, walks through his complete personal productivity system built on top of ChatGPT Work and the Codex app. He demonstrates how he uses long-running pinned threads, scheduled automations, custom skills, and browser/computer use to manage his entire work life — from reading emails and Slack to shipping code and booking flights. The core argument is that Codex is best thought of as a persistent, trainable collaborator that improves through specific iterative feedback rather than a one-shot tool. The video is most relevant to technical PMs, developer advocates, and power users who want to build a deeply personalized AI-driven operating system for knowledge work.

## Key insights
- **ChatGPT Work vs. Codex are essentially the same engine with different UX** — Work hides git history and code details behind a cleaner interface, making it better for non-code tasks like drafting slides or managing email. Jason now does most of his work in Work because he rarely needs to review the underlying code.
- **Model/effort selection defaults to Solo Medium** — Most daily operational work (reading Slack, scheduling, email triage) doesn't require high intelligence. He only escalates to Extra High or Ultra when building complex prototype applications that need to run autonomously for hours.
- **Everything lives in one project: the Vault** — Jason uses a single Obsidian vault (plain markdown files) as the universal context for all his agents. It contains directories for projects, people, notes, daily notes, and preferences. This single source of truth travels with him across environments (local, cloud, GitHub).
- **Pinned threads as workspaces** — Rather than hundreds of ephemeral threads, Jason maintains a small set of pinned long-running threads, each representing a project or domain. Compaction handles context management automatically so prior context is never lost.
- **Chief of Staff automation runs 3x daily (9am, 1pm, 5pm)** — It reads all Slack messages, Twitter DMs (via computer use), unresponded emails, and his Linear board, then surfaces a prioritized digest. If Linear tickets need status updates, Codex handles them automatically. It also checks flight bookings and texts him boarding passes.
- **Skills are trained on your own voice and evolve over time** — Jason has a "write me" skill, "tweet me" skill, "email me" skill, and a skill that turns voice transcripts into blog posts. These are initially generated by having Codex read hundreds of past messages/tweets to learn his voice, then refined iteratively. He distinguishes between tone for executives, teammates, and external users.
- **Self-improve skill audits skill usage across past sessions** — A meta-skill reads the 400 most recent sessions, identifies which skills were never invoked, surfaces consistent feedback patterns, and recommends consolidations (e.g., merging separate Slack/email/write skills into one). Codex stores all sessions as JSON and can query them.
- **Skills vs. Plugins distinction** — A skill is one component (a prompt + behavior). A plugin is a bundle of multiple skills, MCP servers, scripts, and resources that can be shared with a team. Jason would package his writing skills into a "better writing" plugin. As of the recording, users can now submit plugins to the Codex plugin directory.
- **Browser use tip: open research results as tabs, not markdown** — Instead of asking for a research summary document, Jason asks Codex to open each product/result in its own browser tab so he can review and decide manually. The Codex browser supports logged-in sessions (cookies) and multi-tab control.
- **Computer use for form-heavy automations** — He uses computer use to automate downloading CSVs from Airtable (no API available), moving files, and testing apps. The bike ride story: Codex used computer use to find a video file, re-export it with subtitle fixes, post it to Slack, and then loop every 30 minutes to incorporate feedback — all while he was away from his laptop.
- **App building workflow: Goal MD + Plan MD + Worklog** — For the drum learning app, he first had a long conversation with Codex to define what he wanted to build, then generated a Goal MD (success criteria with verifiable tests, e.g., "open the app via computer use, upload this YouTube URL, get drum data back"), a Plan MD (implementation details: React, Tailwind, Shadcn, specific tabs), and a running Worklog. The goal file can be edited at any time to expand scope without restarting the agent.
- **Let Codex write its own goals** — Jason explicitly recommends not writing goal files yourself. Describe success criteria conversationally, then instruct Codex to formalize its own goal. Model-generated goals are typically more precise and testable.
- **The "only job left" is taste and specificity** — Jason's thesis: coding is solved, so the skill that matters now is the ability to articulate what you dislike about something. Saying "make it better" 20 times produces weak results. Saying "the tempo slider flickers because the page isn't eagerly loading — fix that" produces progress. The craft has shifted from writing code to developing taste and vocabulary.
- **Autonomous cloud execution is the next frontier** — Codex is moving more automation into the ChatGPT Work cloud experience so tasks continue running after the laptop closes. Jason sees this as the most exciting near-term development.

## Use cases
- **Developer advocates and technical PMs** who manage high volumes of Slack, email, and Linear tickets and need a daily triage system without manual effort.
- **Frequent travelers** who want automated flight check-ins, boarding pass delivery via SMS, and calendar management from a single AI system.
- **Anyone publishing content** (tweets, blog posts, emails) who wants a voice-trained writing assistant that drafts in their style across different audiences and tones.
- **Solo builders and indie hackers** who want to grow a prototype application incrementally over days or weeks using long-running Codex goals rather than one-shot prompts.
- **Teams wanting to share AI tooling** via the Codex plugin directory — packaging skills + MCP servers into a distributable plugin.
- **Non-engineers learning a skill** (e.g., music) who want to build a fully custom interactive learning tool tailored to their own progression rather than using off-the-shelf apps.
- **Anyone doing repetitive form-filling or file management** (e.g., downloading CSVs from Airtable, organizing downloads) who can replace the workflow with computer use automation.
- **Knowledge workers with Obsidian vaults** who want to use their existing markdown notes as persistent agent context across all tasks.

## Patterns & frameworks

**Chief of Staff Loop**
A scheduled automation (9am/1pm/5pm) that reads all communication channels (Slack, email, Twitter DMs, Linear) and produces a prioritized digest with links to pre-drafted responses. Over time it gains additional behaviors like auto-updating Linear statuses, checking flights, and sending boarding passes. Built by telling Codex "turn this thread into a heartbeat" and then iterating on preferences.

**Goal MD + Plan MD + Worklog**
A three-file scaffolding for long-running app builds. The Goal MD defines verifiable success criteria (e.g., "use computer use to open the app, upload this YouTube URL, and return drum track data"). The Plan MD specifies implementation details (tech stack, architecture). The Worklog captures agent progress and blockers as a running log for human review. Goals are written by Codex, not the human, and can be edited mid-run to expand scope.

**Ultra Goal / Long-Running Agent Pattern**
A skill that loads a goal file and runs Codex autonomously (on Extra High or Ultra effort) for hours or days, spawning sub-agents as needed. The goal file acts as the persistent instruction set; compaction handles context. Used for complex builds like the drum app.

**Self-Improve Skill**
A meta-skill that queries past session JSON, identifies the most-called skills, reads the session transcripts of those skills, surfaces consistent feedback patterns, and recommends updates or consolidations. Runs periodically or on demand to keep the skill library lean and well-calibrated.

**Voice Training via Historical Data**
To create a personalized writing skill, instruct Codex to read N past messages/emails/tweets and extract stylistic patterns, then segment by audience type (executive, peer, external). The resulting skill drafts in your voice and can be updated by re-running it against fresh historical data every few weeks.

**Tab-Based Research Presentation**
Instead of producing a markdown summary of research findings, instruct Codex to open each result in a separate browser tab. The human reviews tabs and decides manually, preserving human judgment on final decisions while offloading all research and navigation.

**Iterative Taste Development (core philosophy)**
The meta-framework underlying everything Jason does: start with a rough output, identify specifically what you dislike (not "make it better" but "the tempo slider flickers because X"), feed that specific dissatisfaction back to Codex, and repeat. The skill being developed is taste + vocabulary, not technical knowledge. Applied equally to skills, apps, and writing.
