# Agentic Engineering vs Software Engineering: Beyond Vibe Coding

Video ID: `FgaBdwSvOGM`

## Summary
The video distinguishes between software engineering and agentic engineering, tracing a spectrum from traditional coding to fully autonomous AI-driven development. It argues that agentic engineering is not a replacement for software engineering but an evolution of it — shifting developer effort from writing explicit logic to orchestrating, supervising, and validating probabilistic AI systems. The speaker addresses both the opportunities and risks of this shift, emphasizing that human expertise becomes more valuable, not less, as AI systems grow more autonomous.

## Key insights
- **There is a spectrum of AI-assisted development**, ranging from traditional software engineering → AI-assisted coding → vibe coding → agentic coding → agentic engineering, each representing progressively more delegation of agency to AI systems.
- **Agentic engineering is defined by two roles**: "agentic" (AI agents that write and iterate on code) and "engineering" (human expertise required to oversee, validate, and maintain quality throughout).
- **Traditional software engineering is deterministic; agentic systems are probabilistic.** Bugs in traditional systems are traceable; agentic systems can appear correct while making flawed decisions, hallucinating, or producing architecturally poor output.
- **Human oversight becomes more valuable, not less**, as autonomy increases — engineers are now responsible for reliability across probabilistic workflows, not just deterministic ones.
- **Vibe coding has a ceiling.** It excels at rapid prototyping but accumulates technical debt quickly without engineering discipline — unstructured AI-generated code becomes hard to maintain.
- **The core engineering bottleneck shifts** from writing every line of code to orchestrating, constraining, supervising, and evaluating autonomous systems.
- **These categories are not rigid** — teams often start with vibe coding to prototype, then graduate to agentic coding and agentic engineering as complexity and stakes grow.
- **Practical advice**: Start small, integrate AI tools into your current workflow, observe where they help and where they fail, and never substitute automation for genuine understanding.
