# What Is LLM Inference? How AI Models Generate Responses

Video ID: `615-yWyS1n0`

## Summary
This video explains how LLM inference works — the process that turns a trained model's static weights into live responses. It covers the full request lifecycle from tokenization through GPU routing, batching, and the two core inference phases: prefill and decode. The video also introduces key performance metrics and explains why inference costs more over time than training.

## Key insights
- **Inference vs. training**: Training happens once and can cost hundreds of millions of dollars, but inference recurs with every single request — making it more expensive in aggregate over a model's lifetime.
- **Tokenization is the entry point**: Before any compute happens, text is broken into tokens mapped to IDs. Models only see token IDs, never raw text. Larger vocabularies encode text more efficiently but add training overhead.
- **Batching keeps GPUs efficient**: Processing requests one at a time wastes GPU capacity. Inference engines use *continuous batching* — slotting in new requests as soon as others finish — to maintain near-full GPU utilization.
- **Two distinct phases — prefill and decode**: Prefill reads the entire prompt at once and builds the KV cache (compute-bound, needs raw parallel math). Decode generates tokens one at a time using that cache (memory-bandwidth-bound, needs fast data movement).
- **The KV cache prevents exponential slowdown**: By caching keys and values from the prompt, the model avoids reprocessing the full conversation on every token generation step.
- **Two key latency metrics**: Time to First Token (TTFT) measures prefill duration; Inter-Token Latency (ITL) measures each decode step. Together they define the user-perceived latency of a model.
- **Inference engines abstract hardware complexity**: Tools like vLLM, Ollama, and llama.cpp handle request scheduling, GPU resource management, and routing — typically behind an OpenAI-compatible API so applications can swap models without code changes.
