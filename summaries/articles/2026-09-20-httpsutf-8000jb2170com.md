# UTF-8000: Unlimited UTF-8

Source: https://utf-8000.jb2170.com

## Summary
UTF-8000 is a proposed extension of the UTF-8 encoding scheme that allows arbitrarily large code units (beyond UTF-8's current 4-byte maximum), enabling encoding of unlimited codepoints. It is a strict superset of UTF-8, which is itself a strict superset of ASCII, meaning all existing UTF-8 data is valid UTF-8000. The proposal introduces no new special cases beyond the two already inherited from UTF-8, and preserves all desirable properties like self-synchronization, self-punctuation, and `strcmp`-compatible ordering. A reference Python implementation is available via `pipx install UTF-8000`.

## Key takeaways
- **Backward compatible**: ASCII ⊆ UTF-8 ⊆ UTF-8000 — no changes to existing encodings.
- **Arbitrary length**: Code units can be 1 byte (ASCII), up to 4 bytes (UTF-8), or any number of bytes beyond that (UTF-8000), encoding arbitrarily large integers as codepoints.
- **Content bit formula**: An n-byte code unit stores `5n+1` content bits (for n > 1), so information density approaches 62.5% as n grows.
- **Only two special cases**, both inherited from UTF-8: ASCII's 7-bit content (not 5n+1), and 2-byte units having 4 mandatory content bits instead of 5.
- **Self-synchronization preserved**: The `10` continuation byte prefix and `0`/`11` first-byte prefixes allow random-seek decoding and robust error recovery without global state.
- **`strcmp` ordering preserved**: Bytewise comparison of UTF-8000 sequences correctly orders codepoints without decoding.
- **No endianness**: Like UTF-8, the quantum is a single byte, so byte-order issues don't apply.
- **Sensible limits exist**: Powers-of-16 bit counts correspond to clean code unit lengths (e.g., 51 bytes = 256 content bits), useful for practical caps.
- **Signed integer extension**: A ZigZag encoding layer can be layered on top to efficiently encode signed integers, with small-magnitude values producing shorter code units.
